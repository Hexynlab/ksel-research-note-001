# Security Policy

H3XYN LAB takes security reports concerning this repository and its associated research artefacts seriously.

## Reporting a vulnerability

Please use GitHub's **Report a vulnerability** option in this repository's **Security** tab to submit a private report, if that option is available.

If private vulnerability reporting is not available, do **not** publish exploit details, credentials, personal data, or proof-of-concept material in a public issue or pull request. Instead, open a minimal public issue asking the repository maintainers to provide a private reporting channel. Include no vulnerability details in that issue.

## What to include in a private report

Where safe and relevant, include:

- A concise description of the affected component and version or commit.
- The potential security impact and conditions required to reproduce it.
- Minimal reproduction steps or a proof of concept that does not access or expose third-party data.
- Any suggested mitigation.

Do not include live credentials, private keys, personal data, or unrelated third-party information.

## Coordinated disclosure

Please allow maintainers reasonable time to acknowledge, investigate, and address a report before public disclosure. Coordinate any disclosure involving affected third parties with them where appropriate. H3XYN LAB will aim to keep the reporter informed as the issue is assessed.

This policy complements the [H3XYN LAB Public Disclosure Policy](governance/PUBLIC-DISCLOSURE-POLICY.md). It does not promise a specific response or remediation timeline.
